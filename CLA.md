# NarraFork 贡献者许可协议（CLA）

协议版本：1.2 · [English reference](#english-reference)

本协议提供中英文对照；两种文本出现歧义时，以中文文本为准。

NarraFork 现采用 [Mozilla Public License 2.0（MPL-2.0）](LICENSE)。项目原创代码及配套材料适用该许可证；附有单独许可声明的第三方材料，按其声明处理。本协议是贡献者向维护方授予的独立许可；仅使用或分发项目的用户无需签署。

**签署即表示同意第 3 条：维护方可将已获授权的贡献改以宽松开源许可证发布。**

## 1. 当事人与贡献范围

- **贡献者（“您”）**：签署本协议并拥有相关权利的自然人或法人。代表法人签署的，须获得该法人的有效授权。
- **项目**：官方仓库 `NarraFork/NarraFork` 中的 NarraFork 项目。
- **项目维护方**：拥有并管理 GitHub 组织 [NarraFork](https://github.com/NarraFork)、负责维护项目并接收贡献许可的自然人或法人。
- **贡献**：您有意提交、用于纳入或改进项目的原创代码、补丁、文档、测试及其他材料，包括通过 PR、提交、Issue 附件或其他约定渠道提交的材料。标注为“非贡献 / Not a Contribution”的材料除外。

本协议涵盖：触发本次签署的 PR 中的贡献、签署后提交的贡献，以及经单独补签并列明 PR 或提交哈希的历史贡献。

## 2. 版权许可与权利保留

贡献的版权及未明确授予的其他权利仍归您所有，您可自行使用或许可该贡献。

您向维护方授予全球性、非独占、永久、免许可费、免版税的版权许可，授权其复制、使用、修改、创作衍生作品、公开展示、公开表演和分发贡献，并可按第 3 条再许可。在适用法律允许的范围内，该许可不可撤销，且仅适用于您有权许可的贡献。

维护方须保留适用许可证要求的版权、署名、许可证、免责声明及第三方声明，且不得冒称拥有您的版权；新发布版本可按第 3 条更新许可证声明。使用您的商标、商号或标识进行背书或推广，须另获您的授权。

## 3. 宽松开源再许可授权

您授权维护方在以下范围内发布您的贡献，无需逐次征得您的同意：

1. 现以 `MPL-2.0` 发布；
2. 今后以 **MIT、Apache-2.0 或 BSD-3-Clause** 发布，方式包括单独发布、纳入项目或衍生作品、再许可、多重许可，以及在新版本中替代 MPL-2.0；
3. 以其他经 Open Source Initiative（OSI）批准的宽松开源许可证发布，例如 `BSD-2-Clause`、`ISC`。“宽松”指许可证允许使用、修改和再分发（含商业使用），且不要求公开修改后的源码，或以相同许可证发布修改版本及衍生作品。此类许可证可附带署名、保留声明、免责声明、禁止借名背书或专利条款。

上述授权包括接收者依所选许可证行使权利所需的版权再许可，以及第 4 条范围内的专利再许可。维护方可继续采用 MPL-2.0，并自行决定今后是否更换许可证。

**以专有、闭源等非开源许可证再许可，或作出本条范围以外的许可变更，须另获相关权利人的明确授权。** 宽松开源许可证可能允许下游将贡献用于闭源产品，具体条件以所选许可证为准。

本条仅适用于您有权授权且已纳入本协议的贡献。项目整体更换许可证前，维护方须逐项确认授权；授权不足的材料应保留原许可证并明确标注，或予以移除、替换。

接收者已有效取得的 MPL-2.0 许可，不因日后更换许可证而撤回。仅依 MPL-2.0 取得权利的人，其权利以 MPL-2.0 为准，不享有本协议授予维护方的额外再许可权。

## 4. 专利许可

对于您拥有或有权许可、且因贡献本身或贡献与提交时的项目相结合而必然被实施的专利权利要求，您向维护方及经其分发取得贡献的接收者授予全球性、非独占、永久、免许可费、免版税的专利许可，许可其制造、委托制造、使用、许诺销售、销售、进口和转移贡献及上述结合，并可按第 3 条再许可。

除下述终止情形外，该许可在适用法律允许的范围内不可撤销。仅因后续修改或其他组合而被实施的专利权利要求，不在本条范围内。

任何接收者（含维护方）提起专利诉讼（含反诉或交叉请求），主张您的贡献或上述结合构成直接或间接专利侵权的，您依本协议授予该接收者的专利许可自起诉之日起终止。其他接收者的许可不受影响；独立适用的开源许可证中的专利条款，依其规定处理。

对于您无权依本协议授权的第三方材料，由维护方另行审查是否接收，并记录其许可依据。

提交贡献不会使您负有持续支持、维护、更新或修复的义务。报酬及项目管理权须另行约定；是否接收贡献由维护方决定。除第 5 条所作声明外，贡献按“现状”提供；在适用法律允许的范围内，您不作其他明示或默示保证。

维护方自行负责许可变更、发布合规，以及其对外作出的支持或保证承诺；未经您授权，维护方无权代您承担额外义务。依法不得排除或限制的责任，仍依适用法律处理。

经书面确认的继任维护主体可承接本协议项下的许可，但仅限用于继续维护本项目，并须承担相同义务、遵守原有再许可范围。

## 7. CLA Assistant 签署与记录

### 7.1 默认签署方式

您使用 GitHub 账号登录官方仓库关联的 CLA Assistant，阅读并同意本协议后，本协议即生效。**默认使用 GitHub 账号签署：无需填写法定姓名、发送邮件或等待维护方逐次确认。** 账号认证用于将签署与贡献记录相关联；权属及签署权限仍须符合第 5 条。

提交 PR、添加 `Signed-off-by` 或使用项目，均不构成签署；签署须在 CLA Assistant 中明确同意。

**接入状态：待配置。** 开放签署前，维护方须将固定版本的协议关联至官方仓库。签署服务和合并检查是否启用，以实际配置为准。

### 7.2 签署要求

1. 提交 PR 后，按 CLA Assistant 的提示完成签署；首次签署即涵盖该 PR 中的贡献。
2. 协议版本未变时，后续贡献沿用已有签署；协议更新后，按提示重新签署。
3. 企业贡献须由获得权利人授权的代表签署。对于企业贡献、多人共有或权属存疑的贡献，维护方可要求提供必要证明，相关材料通过私下渠道提交。
4. 补签历史贡献时，须列明对应的 PR 或提交哈希。
5. 合并前，维护方须确认相关贡献者均已签署，并处理权属或授权方面的例外情况。机器人账号可加入白名单免签，但其提交材料的来源及许可依据仍须审查。

### 7.3 版本、记录与隐私

维护方保存各版本协议全文、Gist 修订与仓库提交的对应关系，以及签署账号、签署时间和相关 PR，并定期导出、备份签署记录。补充授权证明仅在必要时收集，并存放于访问受限的位置。

公开 PR 仅显示签署状态；身份资料和授权证明通过私下渠道处理。

1.2 版精简了措辞，并改为默认使用账号签署。已有签署按签署时的文本和授权范围处理；扩大授权范围须重新取得明确同意。
