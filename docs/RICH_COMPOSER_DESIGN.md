## 1. 目标与设计结论

把文字、选中文本引用、文件引用、上传文件和图片放进**同一份可编辑文档**，而不是把附件列表移进输入框边框。

- 文字与 chip / 图片可以交错出现，光标能放在节点前后，支持整体选择、删除、撤销和重做。
- 选中文字只出现悬浮引用提示，不改变输入区或消息列表的布局；确认引用后才修改文档。
- 图片是行内缩略图节点，文件和引用是统一视觉规格的 chip，不再有框外的两排附件。
- 刷新、发送失败、队列编辑、历史消息编辑和全屏编辑保留节点相对顺序。
- 首版的“富文本”指混合内容编辑，不引入 Word 式排版、Markdown 所见即所得或格式工具栏；Markdown 仍按用户输入的字面文本保留。

范围：叙述者 composer 及其全屏、队列编辑、历史用户消息编辑。团队聊天输入框、知识库编辑器及已弃用的 ruler 不在本次重构范围。

## 3. 视觉与布局

### 3.1 基本结构

```text
消息区（选区候选出现时高度、滚动位置不变）

                       ┌ 引用所选内容  Tab  × ┐  ← 悬浮层，不占布局
┌──────────────────────────────────────────────────────────────┐
│ 请结合 [❞ 这段说明 ×] 和 [文件 App.tsx:12–28 ×] 分析          │
│ 这里的差异 [图片缩略图 ×]，相关日志是 [附件 console.log ×]。    │
│ 光标可以插在任意文字与节点之间 |                              │
│                                                              │
│ [附件]                                  [优化] [展开] [发送 ▾] │
└──────────────────────────────────────────────────────────────┘
```

示意中的“图片缩略图”是真实缩略图节点，不是文件名文本 chip。引用、文件、图片按插入位置自然换行，不强行各占一排。

- 单一圆角容器，复用 Mantine 当前主题、边框、焦点色和字号；避免与现有界面割裂。
- 编辑内容区与底部操作区分离；操作区在容器内占固定高度，不覆盖文字，也不随选区提示出现而挪动。
- 默认内容区约三行高（84px），最大 200px，超过后内部滚动；移动端最大 `min(200px, 30dvh)`。这些为初始设计值，浏览器验收后可微调。
- chip 高 24px，文字行高至少容纳 24px，普通 chip 底部对齐，真正单行插入/删除 chip 不改变高度；最大宽 `min(240px, 100%)`，单行省略。图片与自动换行仍可增高；图标表示类别，不能仅靠颜色区分。
- 图片保留比例，缩略图包络最大 96×64px；加载前即预留尺寸，避免解码后跳高。图片不允许被正文撑成大图。
- 删除按钮始终可发现；桌面悬停增强对比，触屏显示常驻按钮，扩展命中区域但不遮挡相邻光标位置。
- 上传/失败/资源缺失状态出现在对应节点内或预留的操作区状态位，不重新生成框外附件条。
- 正文实际增加、用户主动引用或主动插图可以导致合理增高；**被动选中、取消选区、图片解码不允许改变外层高度**。

### 3.2 统一节点样式

| 节点 | 默认显示 | 查看行为 |
| --- | --- | --- |
| 文本引用 | 引用图标 + 摘要 + 删除 | 悬停/聚焦看有界预览；显式“定位来源”操作跳回消息/工具输出 |
| 文件引用 | 文件图标 + 文件名与行范围 + 删除 | 显式操作打开文件；保留 deviceId、完整路径、保存哈希与行列范围 |
| 上传文本文件 | 附件图标 + 文件名 + 大小 + 删除 | 节点菜单查看元信息；不把大文件正文装入编辑器 |
| 图片 | 缩略图 + 状态 + 删除 | 单击选中节点，显式预览操作打开图片查看器 |
| @提及 | 首版保留字面文本 | 继续使用现有候选菜单，不额外引入身份节点迁移 |

普通单击节点用于定位编辑器选择，避免移动光标时意外跳转。预览与定位来源通过明确操作或键盘菜单触发。

## 4. 交互规范

### 4.1 选择与引用：候选不是草稿内容

1. 沿用叙述者作用域和 120ms 选区稳定等待，只有当前面板的合法选区可产生候选。
2. 候选提示 portal 到对应面板所属 Document，优先悬浮在输入框上沿，不跟随鼠标拖选来回移动；空间不足时翻转并限制在可视区域内。
3. 候选不加入编辑器文档，不触发草稿同步、撤销记录或自动增高。
4. 消息/工具候选按钮 pointerdown 阻止默认行为，确认前不抢焦点、不破坏原选区。消息框选后按 Tab 确认，Escape 取消；不抢输入框补全、缩进和普通焦点导航。Monaco 完全保留原生 Tab，不生成输入区文件引用候选；文件选区使用所属编辑器行号旁的原生悬浮按钮。触摸或手写笔触发的消息候选不显示快捷键提示，鼠标、键盘触发显示 Tab；候选控件点击期间不改变提示宽度，兼容混合输入设备。
5. 消息点击引用或按 Tab，文件点击行号旁引用按钮：把原子节点插入所属输入框的上次合法光标/选择位置，没有记录时追加到文末。Monaco 按钮直接读取自身选区、设备、路径和已保存哈希，不依赖全局最后一次选区；有接收方时预留固定侧栏空间，选区变化不挤动代码。未保存、保存中、无可校验哈希或截断预览不可引用。完成后焦点进入输入框并置于节点后。
6. 保存的书签随编辑事务映射，不能只记一个会过时的 DOM Range。切换叙述者或卸载后旧书签失效。
7. 已消费的选区不重复弹出候选；未保存文件的候选显示不可引用原因，不引用未保存字节。
8. 多面板保持现有唯一快捷键所有者规则；不能一次按键向多个输入框插入。

### 4.2 上传、粘贴、拖放

- 附件按钮先保存选择书签，再打开系统文件选择器；返回后在该位置插入，多个文件按选择器返回顺序一次插入。
- 粘贴截图在当前选择处插入图片；纯文本/代码按纯文本粘贴，保留换行和空格，不执行 Markdown 自动转换。
- 拖放到编辑区使用落点光标；拖放到面板其他区域使用上次编辑器书签，缺失则文末。不把附件无条件加到“附件数组尾部”。
- 类型、数量、大小限制沿用当前上传策略。仅在主动发送时上传，不为了布局重构引入后台预上传。
- 资源先进入有稳定 assetId 的资源表，再插入节点；拒绝的文件不产生幽灵节点，提示拒绝原因。
- 图片预览只持有 object URL，不把 base64 写进文档；释放节点视图不等于删除资源，撤销仍可恢复。

### 4.3 光标、删除、撤销与快捷键

- 节点内部不可逐字编辑，方向键可跨过节点；节点前后、相邻节点之间均可落光标。
- Backspace/Delete 在紧邻节点时先选中节点，再按一次删除；点击 × 直接删除。选中范围包含节点时整体删除。
- 输入文字、插入/删除节点、重排节点共用同一撤销栈；插入多个附件视为一个用户操作。
- 本地附件资源保留到相应撤销历史释放或文档生命周期结束，之后再释放 Blob/object URL；不能删除节点就立刻让撤销失效。
- Enter/Ctrl+Enter 沿用发送配置；Shift+Enter 换行。候选菜单打开时优先处理菜单，中文 IME 合成期绝不发送。
- `/`、`@`、`#` 菜单从当前文本节点和选择位置读取查询；不能继续用 textarea.selectionStart 推算整个富文档位置。
- 首版 slash 命令仅在无引用/附件等非文本节点的纯文本命令上下文执行；存在混合节点时不误触命令，显示明确提示或作为普通正文发送。
- Tab 不困住焦点；编辑器具有 textbox、多行、可访问名称，节点动作有中文/英文标签；键盘可进入节点菜单查看来源和删除。

### 4.4 全屏与提示词优化

- 全屏使用同一编辑器控制器与文档/资源状态，切换只改变容器，不生成一份纯文本副本；选择书签与撤销历史保留。
- 优化只作用于选中的纯文本范围；无选择时作用于所有可编辑文本片段。通过带编号文本片段请求、验证响应片段集合后逐段替换，不能把 chip 标签当正文重写。
- 节点及相对顺序不参与优化；异步响应到达时检查文档版本，用户期间有修改则不自动覆盖，提供重新优化提示。取消不改文档。

## 5. 编辑器与文档架构

### 5.1 选型

使用项目已有 Tiptap/ProseMirror 依赖。实现最小 schema：paragraph、text、hardBreak、quote、fileReference、attachment。

- quote/fileReference/attachment 为 inline atom；使用 NodeView 呈现 chip/图片。
- 禁用 StarterKit 的标题、列表、格式 mark、输入规则等非目标功能，不照搬 SpecMarkdownEditor 的格式工具栏。
- 不手写裸 contenteditable 的选区、IME 和撤销实现；也不采用 textarea + 绝对定位覆盖 chip 的伪编辑器。
- 编辑器事务负责文档与选择，React 只订阅必要状态，继续保持输入不逐键重渲染消息列表的现有隔离边界。
- 业务文档独立于 Tiptap 内部 JSON：只在 adapter 中做语义转换，不把任意编辑器 JSON 作为服务器协议。

### 5.2 单一语义文档 + 独立资源表

建议的协议结构（新结构，尚未实现）：

```ts
type ComposerDocumentV1 = {
  version: 1;
  paragraphs: { children: InlineNode[] }[];
};

type InlineNode =
  | { type: "text"; text: string }
  | { type: "break" }
  | { type: "quote"; id: string; label: string; text: string; anchor?: string }
  | { type: "fileReference"; id: string; reference: FileReference }
  | { type: "attachment"; id: string; assetId: string };
```

- 文档只含有界文本与资源身份；asset manifest 包含类型、名称、大小等展示元信息。
- 客户端资源表将 assetId 映射到本地 File，或服务端已有的 imageId / filePath / 队列附件身份；这些绑定不是任意文件读取凭据，必须沿用归属授权。
- occurrence id 与 assetId 分开：节点是一次出现，资源是二进制身份；重名文件不合并。服务端文件引用仍使用现有 occurrence id 和权限边界。
- text、fileReferences、images、textFiles 均由文档快照投影，禁止作为与文档双向独立可写的四份状态。
- adapter 维护“文档位置 ↔ 兼容正文 UTF-16 范围”的映射，现有 FileReference.inputRange 仍指向真实序列化 token，不能装入 ProseMirror position。

### 5.3 两种投影，职责分开

1. **编辑/展示投影**：文档与资源 manifest 保留用户真实顺序。队列、历史编辑和已发送用户消息展示均用同一只读节点渲染规则。
2. **现有模型输入投影**：沿用有界 quote blockquote、#file token、图片和文本文件的现有模型处理路径；引用快照仍由服务器读取并构造，客户端不能提交可信快照。

首版保证用户侧混排位置往返，不承诺各 provider 的原生多模态块顺序同步变化。模型仍能收到现有的文本与附件语义；二进制块交错的模型输入优化另立任务，避免顺带重写全部 provider。

所有兼容字段由一个 adapter 导出；服务端对结构化文档重新投影并校验上传绑定，若客户端同时提交的正文/引用不一致则拒绝，不能各自取一半造成分叉。

## 6. 持久化、传输与兼容

### 6.1 不能只做本地布局 sidecar

建议增加版本化 composerDocument 与 asset manifest，通过草稿、发送、队列编辑、历史编辑的 API/服务传递，并在对应持久化记录中保留布局元数据。

- 草稿表增加可空、有界的文档元数据字段；与现有 revision/sourceId 同一次 CAS 提交。空文档仍写 tombstone。
- 消息与队列持久化文档元数据；最终附件存储后将 manifest 绑定为当前记录授权的资源身份，不存浏览器 blob URL。
- 不把布局包装成未知模型 content block 塞进 provider 历史；布局字段只用于编辑/展示，旧 contentJson/contentText 继续承担既有职责。
- 列表/WS 摘要只返回 hasComposerDocument、版本等小字段，不附带完整文档；打开详情/编辑时按需加载。更新后使对应详情缓存失效。
- 数据库变更只改 server/db/schema.ts 后生成 SQLite/PG 迁移，不手写迁移文件。

### 6.2 草稿的跨端边界

本次不新增服务器草稿文件上传系统：

- 文档布局和附件 manifest 可以随服务端草稿同步；尚未发送的 Blob 仍仅保存在原浏览器 IndexedDB。
- 原浏览器刷新按稳定 assetId 恢复。另一设备或本地存储淘汰后显示“附件需重新选择”节点，保留它的位置，不静默丢失或伪装上传成功。
- 有缺失资源的文档禁止发送；用户可以重新关联文件（校验元信息并明确确认，不仅按同名猜测），或显式移除节点。
- 保留现有附件持久化预算：单文件 20MiB、总量 100MiB、TTL 三天。超出本地持久化预算但符合上传限制的文件可在当前页面发送，明确提示刷新后需重选。
- 本地一次记录保存 documentRevision、assetId 与 Blob 关联，hydration 必须检查 ownerScope 和本地版本；旧异步读取不能覆盖新输入。

### 6.3 历史数据与旧客户端

- 新字段可空；旧数据不批量改写。从旧 quote 前缀和 inputRange 构造引用节点，旧图片/文件按原有分组顺序附加，不能声称恢复了从未保存过的历史位置。
- 旧客户端只提交 text/fileReferences 时继续接受，但该次更新清除过期的结构化布局，防止下次读取错位；更新策略在响应中明确返回文档版本。
- 新客户端加载无布局旧数据走统一 importer；有布局但未知版本时只读降级显示旧正文和附件，禁止无提示地覆盖为新版本。
- 部署顺序为后端接受并持久化协议 → 前端启用新编辑器。旧后端不支持文档时明确降级为旧输入，不伪装支持无损布局。
- IndexedDB 读取旧附件记录后为资源分配稳定身份，迁移写入新记录成功才淘汰旧形态。

### 6.4 发送是一份快照事务

- beginSend 固定文档、资源绑定、ownerScope 和本地版本；上传与服务端提交均消费该快照。
- 成功后只清除对应已发送版本，不能清除用户随后输入的新草稿；失败/取消恢复同一份文档和资源关联。
- 首版在上传/提交期间锁定该文档及资源修改，明确显示发送状态并保留取消；成功或失败后解锁。锁定之前若已产生更高版本的新草稿，不得用旧版本回滚覆盖；失败快照单独保留并提供显式恢复。后续如开放发送中继续编辑，需再增加独立失败草稿槽位。
- 队列已有附件的保留语义（省略=全保留、空数组=全删除）由 adapter 显式转换，不能从节点标签或数组索引猜身份。
- 覆盖正常发送、排队、打断、压缩期发送、/new、聊天转发桥，以及编辑失败保留输入，不只替换发送按钮入口。

## 7. 安全、边界与性能

以下新增协议限制为设计值，实现时放进 shared 常量并在客户端/服务端一致验证：

- 延续正文最多 200,000 字符；quote 最多 8 个、单条 8,000 字符；文件引用最多 16 个。上传类型、单文件大小及总数沿用现有策略。
- 文档与 manifest 合计最多 2MiB UTF-8，paragraph + inline 节点合计最多 4,096 个；schema 固定两层，拒绝嵌套 atom、未知类型、重复 occurrence id、悬空/越权资源绑定。
- 正文及 quote 内容共同计入文本预算；导出后的兼容正文也必须满足上限，不能借节点元数据绕过字符限制。
- 不接受 HTML、脚本、任意远程图片 URL、data URL、客户端文件快照正文或可信服务端资源路径；外部 HTML 粘贴只取有界纯文本。只允许受控 object URL/鉴权资源的图片展示。
- 内部剪贴板可保存有界语义片段；粘贴时重新生成 occurrence id。文件引用保持设备作用域，附件没有可用且授权的资源绑定则成为缺失节点；外部剪贴板使用可读纯文本，不复制 Blob/base64。
- 文档转换/校验有明确大小上限，持久化使用 debounce 与现有 CAS。光标移动不全量重建文档；输入事务不触发整块消息列表重渲染。
- 大文件不读入编辑器 JSON；缩略图预处理并发最多 2，单任务 5s 超时且可取消，使用 worker/异步解码，失败仍显示固定尺寸占位与可发送的原文件。
- 上传使用现有有界/超时/取消机制；新文档解析、API请求和草稿写入不引入同步 FS、大聚合或主线程大图解码。
- 新增开发态慢日志：文档转换/校验超过 16ms 或输入事务超过 50ms 时记录耗时、节点数与字节数，不记录私密正文。若真实 200k 字符基准超预算，转移导出到 worker 或缓存增量投影后再验收。

## 8. 实施拆分

### A. 文档协议与纯函数适配

- 定义 shared 的语义文档、manifest、限制、validator。
- 实现旧输入 importer、兼容发送 exporter、UTF-16 位置映射和资源一致性校验。
- 为 quote、同名附件、重复引用、Unicode、空文档与超限输入建立 round-trip 测试。

### B. 核心编辑器与无跳动引用

- 实现最小 Tiptap 编辑器、inline NodeView、统一 chip/图片样式与附件按钮工具区。
- 替换 textarea 依赖的光标、查询、快捷键、ownsTextarea/聚焦接口；保留输入状态子树隔离。
- 拆出悬浮 QuoteCandidate，候选不参与正文布局；迁移选择保留与跨面板快捷键。
- 上传/粘贴/拖放通过文档 command 插入，资源表接管原分类型数组的可写职责。

### C. 完整持久化与发送恢复

- 扩展草稿/消息/队列 API 和存储；沿用服务端权限、文件快照和实际附件处理。
- 迁移 IndexedDB 资源关联、CAS 冲突和两阶段发送快照。
- 已发送消息展示读取布局元数据，旧消息仍可按原数据展示；没有布局时不编造顺序。

### D. 复用编辑器及回归

- 全屏、提示词优化、输入历史、队列编辑、历史用户消息编辑全部使用统一文档 adapter。
- 新 UI 稳定后移除独立框外附件条与引用条；不能先删掉旧行为再留下无法恢复的发送分支。
- 国际化同时更新英文与简体中文。增加受控开关，回退旧编辑器时提示混合布局不可编辑，禁止静默丢弃。

A–D 为同一功能的分步落地，不把只完成 B 的视觉原型当作完整上线。

## 9. 可观察验收标准

### 布局与操作

- 连续选中/取消消息及工具输出文字 20 次，消息列表高度、composer 外层高度、列表 scrollTop 与原选区位置保持不变（允许小于等于 1px 的测量误差）。文件编辑器选区也不撑高输入区。
- 候选出现前后选区内容一致；鼠标继续拖选无目标位移。确认后只产生一次插入事务。
- 文档可输入“文字 A → 引用 → 文字 B → 图片 → 文件 → 文字 C”；节点前后均可放光标，选择删除与撤销/重做恢复完整顺序。
- 图片解码前后节点包络尺寸不变；超过最大高度只滚动编辑器内部，操作区不被挤走。
- 320px 窄屏、中文 IME、移动端软键盘、深浅主题、弹出窗口及多面板快捷键均可操作。

### 数据与兼容

- 上述混排用例在刷新、全屏切换、输入历史召回、发送失败/取消、队列重新编辑、历史消息重新编辑后顺序一致。
- 同名不同内容文件不串资源；删除后撤销仍可恢复；缺失 Blob 明确标记并阻止无提示发送。
- 跨设备恢复文档布局但未上传附件显示需重选；不承诺当前架构没有的跨端 Blob 同步。
- 草稿 409 冲突、迟到 hydrate、用户/叙述者切换、发送后输入新内容均不丢文档。
- 新旧协议互通、旧消息 importer、未知文档版本降级、无效资源绑定与超限拒绝均有测试。
- 模型输入包含与旧流程等价的引用正文、文件快照与附件；布局元数据不泄漏到 provider。

### 验证方式

- 按项目 docs/TESTING.md 运行相关测试，子集使用 `bun test --isolate <路径>`。
- 运行 `bunx tsgo --noEmit`、对变更文件执行 Biome、前端构建及 i18n 校验。
- 通过真实浏览器脚本测量 boundingClientRect / scrollTop / selection，并记录光标跨 atom、IME 与图片加载行为；不能仅凭 DOM mock 宣称无跳动。
- 用 200k 字符和最大合法节点量测输入事务与转换耗时；输入不引起消息列表逐键重渲染。
- 不停止、重启或接管承载当前会话的 NarraFork 进程；浏览器验证使用独立开发端口或由用户自行重载。
