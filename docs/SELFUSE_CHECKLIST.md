# selfuse 合并与升级固定检查清单

用于合并上游、升级自用版本时保护本地功能。**最高优先级是 Codex 缓存优化和远程压缩**，其次是 Composer、引用评论、Tab、Git 手动扫描和 GenUI 修复。

这是可重复使用的验收清单，不是某次测试的通过记录，也不授权自动提交、部署或推送。每次记录实际检查结果；新增长期保留的自用功能时，同步更新本清单。

## 1. 执行范围与顺序

- 记录本地基线和上游目标的 commit/tag，确认工作区现有改动的归属。
- 先核对上游是否已提供等价实现；保留功能和行为，不机械保留两套代码。不要恢复已取消的自定义文件相对路径标题或已退役的 nf-openui Skill、提示词。
- 默认顺序：合并并解决冲突 → 隔离服务自测 → 保留服务供用户体验 → 用户确认后提交 merge。当次用户明确指定其他顺序时，按当次要求执行。
- 下方核心项是上游合并后的固定检查项，可以组合成少量连续操作；其他项根据冲突和实际改动选择。**不跑本地全仓测试，不把合并扩大成无关重构或历史问题清扫。**
- 自动测试只运行相关文件，并使用 `--isolate`。使用项目锁定的 Bun 和兼容的 Node，不误用全局旧运行时。
- 同一份代码已经通过功能验收，随后仅打包、部署时，不再重复整套功能测试；执行部署检查即可。代码又有变化时，重验受影响项。

## 2. 隔离测试环境

- 使用独立临时 HOME、NARRAFORK_HOME 和数据库，不能拿正式服务做测试。复制配置时仅取必要的测试 provider，不在日志、截图或报告中暴露凭据。
- 前后端监听用户可访问的局域网地址；本机通常使用 `192.168.119.105:17778/17779`，启动前核对实际地址、端口占用，不能只监听 127.0.0.1。
- 记录本轮服务 ID、端口、测试目录和浏览器窗口，便于准确停止、清理。
- 使用真实浏览器点实际入口，不能用 mock 通过、接口返回成功代替交互验收。
- 移动交互先做窄屏检查；窄屏模拟不冒充真机验证。明确交给用户体验的手机项目。
- 真实模型验证使用已配置的 **Luna**，用少量请求完成连续流程，不默认使用 Astra 等更贵模型。

## 3. 核心功能：每次上游合并后检查

### 3.1 Codex 缓存与反思

- [ ] 普通请求 → 通过正常流程触发工具反思、计划反思 → 返回普通请求，均能继续执行。不能在普通回合直接调用反思决策工具来冒充反思测试。
- [ ] 记录冷请求与后续请求的输入 token、缓存命中 token；不因切换反思而出现可复用前缀无故失效。以真实使用记录或响应为证据，不只看调用成功。
- [ ] 反思中的工具限制仍有效；退出反思后，普通工具和 ToolSearch 动态加载的工具可以调用。核对 `allowed_tools`、动态工具声明与 NF 执行权限检查的兼容。

### 3.2 Codex 远程压缩

- [ ] 在同一 Luna 会话中执行“发几条消息 → 远程压缩 → 继续发消息 → 再压缩”，压缩后能接着使用之前的信息。
- [ ] 压缩请求仍复用普通请求的模板、工具声明和缓存标识；普通请求后紧接的压缩有真实缓存命中，不能只验证普通聊天的缓存。
- [ ] 压缩 usage、缓存 token 和使用记录正常，不无故归零；失败请求仍接入 request dump 逻辑。
- [ ] WebSocket 压缩能正常完成，不与反思、Composer 或后续普通请求发生连接占用冲突。若实际走 HTTP 回退，记录真实传输方式和缓存结果，不能将回退成功写成 WebSocket 已通过。

可将缓存、反思、动态工具和压缩串在同一个测试会话中，避免反复新建会话、重复付费请求。失败 dump 等错误路径优先用相关定向测试覆盖，不为凑项目反复制造线上故障。

### 3.3 Composer 输入建议

- [ ] Codex 专属开关与提示词设置保留；服务端在主代理结束后触发，使用当前模型，子代理不触发建议请求。
- [ ] 第一轮回复后的建议也检查缓存，不只检查聊过多轮后的情况。
- [ ] WebSocket 模式复用空闲连接；建议生成过程中发送用户消息，建议请求被取消，主请求不被占用或阻塞。
- [ ] 建议显示为 placeholder，不变成实际草稿正文；建议出现、选择引用和取消引用时，输入框高度不来回跳动。

### 3.4 逐条引用评论与文件引用

- [ ] 采用上游引用交互，同时每条引用仍能独立添加、编辑、删除评论；评论与对应引用不会串位。
- [ ] 固定引用后在上方打开评论编辑框；点击主输入框或外部空白可关闭。手机弹出虚拟键盘时不丢焦点，已发送评论弹层可以正常关闭。
- [ ] 文件源码、Markdown 渲染视图均可选中引用；带正确文件路径和行号，不只是纯文本。发送后不出现重复文件标题、原始 `#file` 标记等错误展示。
- [ ] 已发送引用可跳回来源；能精准匹配时高亮引用文字。
- [ ] **高度回归步骤：加入 8 条引用 → 在输入框全选并一次删除 → 不再点击输入框，直接选择对话正文。** 待引用条不能额外留下空行。不能用“逐条删除”代替这个用例。
- [ ] 在 Composer 建议可见时重复选中、取消引用，输入框高度仍稳定。

### 3.5 Tab 快捷键

- [ ] 没有待引用内容时，从正文或空白区域按 Tab，优先进入主代理输入框；主代理、子代理并列时不被子代理抢走。
- [ ] 有待引用内容时，Tab 按引用逻辑固定引用并打开评论编辑框；Alt+Q 固定后清除旧选中态和复制悬浮按钮。
- [ ] 在文件面板选中文字后直接按 Tab，可以引用并打开评论，不必先点击叙述者。
- [ ] 从 GenUI 背景等非编辑区域按 Tab，原有主输入框快捷行为有效；组件内部真正的文本输入和表单键盘操作不被错误接管。

### 3.6 Git 检测与手动扫描

- [ ] 机器级默认值与会话开关保留；本机默认开、Mini 默认关的已有配置不被升级覆盖。
- [ ] 根目录 Git 与 polyrepo 子仓库均可发现，子目录遍历最多 3 级。
- [ ] 关闭检测时，打开 Git 面板不会扫描；点击“扫描一次”才加载仓库、变更和 diff，开关仍关闭。
- [ ] **必须在页面 WebSocket 已连接时实际点击扫描。** 状态请求正常发出、转圈结束，不能只测未连接 WebSocket 的环境。
- [ ] 手动结果不会订阅 Git 持续推送，也不会因窗口聚焦、网络恢复而循环扫描；再次点击才刷新。切换工作目录后不能继续显示旧目录结果。
- [ ] 打开自动检测后，原自动模式仍正常。

### 3.7 GenUI 本地修复

GenUI 主体来自上游，这里检查我们额外修过的行为。

- [ ] 桌面、窄屏和低详细程度下，`render` 都能显示实际组件；检查标题、复选框、按钮等真实交互。
- [ ] 长内容正常展开，收起后高度能恢复；下拉菜单开关不留大片空白，不额外引入多层滚动。
- [ ] 较长的组件源码、刷新页面和重开历史会话后，仍显示组件，不能退化为“Rendered inline…”普通工具输出。
- [ ] 区分 `render` 与 `inspect`：后者展示截图及“Preview captured…”说明可以是正常结果，不当成同一种渲染失败。

## 4. 按冲突和改动范围补测的本地功能

相关路径被改动、出现冲突或用户报告异常时补测；无关改动不重复跑整套。

- 人工创建子代理：工具栏按钮可直接创建，正确复用主代理创建时的模型、effort，保留与主代理沟通的能力。
- ExitPlanMode：未自动开启计划反思时，仍可通过按钮手动触发；可与核心反思检查合并完成。
- 运行时间显示：上轮耗时不把空闲时间算进去，“上轮结束距今”正常更新。
- 消息调度：“立即中断并插入”后会继续处理消息；界面空闲时不无故永久排队。
- 草稿：消息发送后，切走再回来不会重新出现已发送正文；注意慢响应、切换会话场景。
- 文件面板：Markdown 默认渲染，重复点击链接不无故变成编辑；“关闭其他”保留当前标签并正确关闭其余标签。

## 5. 用户要求打包、部署时再执行

- [ ] 只提交授权范围的代码；独立功能、修复分别提交。构建产物对应实际提交，使用现有完整构建流程，不省略前端和资源。
- [ ] 保持固定签名证书、标识和实际安装路径；不改用 ad-hoc 签名，不自行更换证书。
- [ ] 核对是否存在待执行迁移。无 schema 变化不盲目生成迁移；有迁移时走既有备份和验证流程，不跳过安装器检查。
- [ ] 使用现有安装器。自动备份、部署暂存只保留最近一次；仅清理明确归属的旧产物，数据库、附件、历史归档和特殊 KNOWN-GOOD 恢复件不按临时文件删除。
- [ ] 仅部署当次授权的机器。本机使用内置管理工具：先 `get_update_status`，再将实际 `preparedIdentity.id` 传给 `apply_update`。
- [ ] Mini 先核对健康接口声明 `SIGUSR2`、正式 launchd PID 与实例锁一致、目标包已准备，再发送一次信号。活动任务交给协调器等待安全点，不强杀。
- [ ] 不新增 launchd 部署任务、KeepAlive 重启任务或 watchdog。请求受理不等于升级完成，也不因等待而重复发信号。
- [ ] 实际核对目标版本、健康状态、进程更替和优雅交接记录；确认备份与暂存保留结果。不同机器分别验收，不拿本机成功替代 Mini 结果。

## 6. 收尾与结果记录

- 用户还要体验时保留测试服务，提供地址、临时账号和需要关注的交互；不要提前停掉。
- 用户完成体验后，停止本轮测试服务，关闭本轮专用浏览器窗口，删除本轮测试目录、测试数据库和临时凭据。不要遗留部署脚本、重复二进制、日志堆积到工作区根目录；需要保留的原始诊断证据明确说明。
- 记录本轮基线／目标 commit、实际运行的定向测试、真实模型缓存与压缩结果、浏览器已验证项目、待用户真机验证项目。
- 对未通过项注明新回归还是已有问题、具体影响和下一步；不能把“未测”“HTTP 回退”“仅自动测试通过”记成完整实测通过。
- 检查工作区状态；提交、打包、安装、优雅重启、push 分别报告实际完成情况。没有当次 push 授权就不推送。
